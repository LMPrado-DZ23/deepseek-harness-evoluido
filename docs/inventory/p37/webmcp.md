# P37 — webmcp

Inventário de referência externa produzido ANTES de qualquer linha de código de
WebMCP entrar no repositório, como o produto exige. Diferente dos inventários de
produto (Lovable, v0, Zed), a referência aqui é uma ESPECIFICAÇÃO, não um
programa: o que se consome é o formato de uma API do navegador, e nenhuma linha
de código de terceiro é copiada.

- projeto: WebMCP (Web Model Context Protocol) — proposta de API nativa do navegador, sob `document.modelContext`, pela qual uma página REGISTRA ferramentas que um agente do navegador pode descobrir e executar. Incubada no W3C Web Machine Learning Community Group / Working Group.
- url: https://github.com/webmachinelearning/webmcp (explicador e rascunho de especificação); rascunho renderizado em https://webmachinelearning.github.io/webmcp/; documentação de implementação do Chrome em https://developer.chrome.com/docs/ai/webmcp
- licenca: W3C Software and Document License 2023 (https://www.w3.org/copyright/software-license-2023/). NÃO é MIT — uma leitura apressada da presença de `LICENSE.md` sugeriu MIT, e o arquivo lido desmente isso. É exatamente o tipo de suposição que este inventário existe para impedir.

- redistribuivel: não se aplica — NADA é redistribuído. O DZ23 implementa CONTRA a especificação (chama `document.modelContext.registerTool` quando o navegador oferece), do mesmo modo que implementa contra `fetch` ou `AbortSignal`. Não há arquivo, trecho de código, tipo ou schema copiado do repositório para dentro deste. Se um dia houver cópia — por exemplo de uma definição TypeScript da API — a W3C Software and Document License exige preservar aviso de direito autoral, a licença e um aviso de modificação, e este inventário terá de ser reaberto antes disso.
- marcas: "W3C" e "WebMCP" são de terceiros. A licença de software e documento do W3C NÃO concede direito de marca. Uso permitido: dizer que o produto implementa a especificação WebMCP e apontar para ela, como este documento faz. Uso proibido: sugerir endosso do W3C, do Google ou do grupo de trabalho, ou apresentar o DZ23 como implementação de referência ou certificada.
- dependencias_e_lockfiles: nenhuma dependência nova entra no `package.json` por causa disto. A API é do NAVEGADOR: quem a fornece é o Chrome (origin trial), não um pacote npm. Existem pacotes de terceiros que emulam WebMCP (por exemplo os exemplos de `WebMCP-org`); NENHUM deles é usado, e usar um exigiria outro P37 próprio.
- rede_filesystem_segredos: a especificação em si não faz rede, disco nem segredo — é uma API de registro dentro da página. O RISCO real está em outro lugar e é o ponto central deste inventário: quem executa a ferramenta registrada é um AGENTE do navegador, que não é o DZ23 e não é a pessoa. Uma ferramenta registrada é, na prática, uma porta de comando exposta a um programa de terceiro rodando na mesma sessão autenticada da pessoa — inclusive com o cookie de sessão do Studio. O explicador chega a recomendar "Trust the agent" ao redigir descrições, o que é conselho de ergonomia e NÃO uma garantia de segurança. Consequência para o DZ23, decidida aqui: nenhuma ferramenta WebMCP pode contornar a autorização, o escopo ou a confirmação que a mesma ação exige pela interface; nenhuma pode tocar cofre, publicação, parada de emergência ou remoção; e nada é registrado sem a pessoa ligar explicitamente.
- cves_conhecidas: nenhuma CVE localizada — a especificação não é software distribuído, e a implementação que existe é do próprio navegador, sob origin trial a partir do Chrome 149. Ausência de CVE aqui não é sinal de segurança: a superfície de risco é de DESENHO (agente de terceiro com poder de ação na sessão da pessoa), não de implementação nossa, e está tratada no campo acima e na ADR.
- sbom: não se aplica — nenhum artefato de terceiro entra na árvore, então não há componente novo para constar no SBOM do produto. O SBOM do DZ23 continua o mesmo depois desta frente.
- sast: não se aplica a código de terceiro (não há). O código NOVO do DZ23 que fala com esta API entra normalmente no `pnpm typecheck`, na suíte, no `gate:secrets`, no `gate:i18n` e na mutação dirigida, como qualquer outro caminho do produto.
- poc_isolado: NAO_VERIFICADO em navegador real — motivo objetivo e verificável: `document.modelContext` só existe a partir do Chrome 149 sob origin trial ou com `chrome://flags/#enable-webmcp-testing`, e o Chromium disponível neste ambiente (build 1194) não oferece a API. A prova possível aqui é contra um dublê FIEL da superfície da API (registerTool/getTools/executeTool/toolchange/AbortSignal/NotAllowedError), e é isso que os testes fazem — sem afirmar em lugar nenhum que o caminho de navegador real foi exercitado.
- veredito: sim, pode implementar — e não há o que copiar. A implementação é contra a especificação, com detecção de capacidade (`'modelContext' in document`) e DESLIGADA por padrão. As três linhas que não se cruzam, decididas aqui: (1) nenhuma ferramenta faz o que a interface não faria com a mesma autorização e a mesma confirmação; (2) nenhuma ferramenta toca segredo, publicação, parada de emergência ou remoção; (3) nada é exposto a origem de terceiro — sem `exposedTo`, o padrão da própria especificação (mesma origem e agente embutido do navegador) é o teto.
