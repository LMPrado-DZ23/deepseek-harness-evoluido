# P37 — Lovable (REF-lovable)

Inventário de referência externa. Nenhuma linha de código deste projeto foi
copiada para este repositório. Campos que não foram confirmados na fonte estão
marcados `NAO_VERIFICADO` com o motivo.

- projeto: Lovable — plataforma SaaS fechada de geração de aplicações web por prompt (Lovable AB / Lovable, empresa sueca)
- url: https://lovable.dev/ (produto) e https://docs.lovable.dev/ (documentação); organização pública no GitHub: https://github.com/lovablelabs
- licenca: proprietária/sem licença pública — o produto Lovable não publica código-fonte sob licença nenhuma; a organização https://github.com/lovablelabs só publica ferramentas de infraestrutura (neon-operator, wide-event, maglev-hash, mcp, molnctl sob Apache-2.0; pg-schema-diff sob MIT), nenhuma delas é o produto
- evidencia_licenca: Termos em https://lovable.dev/terms lidos em 2026-09-08 — "all rights, title, and interest in and to the Services and Lovable Materials" ficam com a Lovable, e o usuário recebe apenas licença "limited, non-exclusive, non-transferable"; os mesmos termos proíbem "reverse engineer, decompile, disassemble, or otherwise attempt to derive source code, models, or algorithms underlying the Services". Listagem da organização lovablelabs conferida na mesma data.
- redistribuivel: não — não existe código-fonte publicado do produto e os termos vedam expressamente derivar ou redistribuir a implementação; o único material redistribuível é o código que O PRÓPRIO USUÁRIO gera na plataforma ("you own any AI Output generated for you through the Services"), que não é o que este P37 avalia
- marcas: "Lovable" é nome comercial e marca da empresa, e o logotipo é obra protegida; não há concessão pública de uso de marca nos termos — o que os termos concedem é o inverso (o cliente concede à Lovable licença de usar o nome e o logo DELE em material de marketing). Uso permitido para nós: citação nominal e referencial ("comparado a Lovable"); uso proibido: qualquer emprego de nome ou logo que sugira origem, endosso ou compatibilidade oficial.
- dependencias_e_lockfiles: NAO_VERIFICADO — motivo: não existe repositório público do produto, portanto não há package.json nem lockfile observável; a stack só é inferível pela saída gerada (React + Vite + Tailwind + shadcn/ui + Supabase, conforme docs.lovable.dev), e inferência não é evidência de árvore de dependências
- rede_filesystem_segredos: rede — serviço 100% hospedado, todo o trabalho ocorre em servidores da Lovable e o app publicado é servido por eles; filesystem — o código do usuário vive no sandbox da plataforma, com sincronização opcional para um repositório GitHub do próprio usuário (docs.lovable.dev, seção de deployment/ownership); segredos — integrações (Supabase, Stripe, provedores de IA) exigem que o usuário deposite credenciais na plataforma, e os termos dão à Lovable "worldwide, perpetual, royalty-free license to use, copy, modify, process, analyze" o conteúdo do cliente, inclusive para treinar modelos. Detalhe interno de isolamento do sandbox: NAO_VERIFICADO — motivo: não há documentação pública de arquitetura auditável.
- cves_conhecidas: CVE-2025-48757 — "An insufficient database Row-Level Security policy in Lovable through 2025-04-15 allows remote unauthenticated attackers to read or write to arbitrary database tables of generated sites", CVSS v3.1 9.3 CRITICAL (CNA MITRE), publicada em 2025-05-29, com o status "disputed" registrado pelo fornecedor no NVD (a Lovable sustenta que a proteção dos dados é responsabilidade do cliente). Fonte: https://nvd.nist.gov/vuln/detail/CVE-2025-48757, consultada em 2026-09-08. Lição para nós: o defeito não estava no gerador, estava no default de RLS do artefato gerado — qualquer gerador nosso precisa tratar RLS como saída obrigatória, não opcional.
- sbom: NAO_VERIFICADO — motivo: a Lovable não publica SBOM do produto e não há artefato para gerar um; nenhuma cópia local existe neste repositório que pudesse ser inventariada
- sast: não executado — motivo objetivo: SAST exige código-fonte, e não há código-fonte do produto acessível; nada foi copiado para cá, então não há nada neste repositório para escanear a título de Lovable
- poc_isolado: nenhum PoC foi feito — motivo: um PoC exigiria criar conta e submeter prompts ao serviço de terceiro, o que envia dados para fora e concede à Lovable licença sobre o que for enviado (termos, cláusula de conteúdo); se um dia for feito, deve ser em conta descartável, com prompt sintético, fora deste repositório, e registrado aqui com data e escopo
- veredito: não se pode copiar código (não existe código publicado e os termos vedam derivá-lo); pode-se estudar o COMPORTAMENTO do produto público — fluxo de prompt, formato de saída, o erro de RLS da CVE-2025-48757 — e reimplementar ideias do zero, sem contato com nenhum artefato proprietário.
