# P37 — Zed (REF-zed)

Inventário de referência externa. Nenhuma linha de código deste projeto foi
copiada para este repositório, e o prompt mestre do produto PROÍBE
explicitamente incorporar código do Zed. Este inventário existe para registrar
por quê, com evidência.

- projeto: Zed — editor de código nativo, multiplayer, de alto desempenho, desenvolvido pela Zed Industries, Inc. (empresa com fins lucrativos, conforme o próprio README)
- url: https://zed.dev/ (produto) e https://github.com/zed-industries/zed (código; HEAD 490aad88d5c754e4b0fbbb2bf1e3d6936df27729 em 2026-09-08)
- licenca: GPL-3.0-or-later na maior parte do código, com componentes Apache-2.0 onde marcado; historicamente o repositório também trouxe AGPL (existiu um arquivo LICENSE-AGPL e crates declarando "AGPL-3.0-only"). Em qualquer das leituras, é família copyleft forte — exatamente o que o prompt mestre veda incorporar.
- evidencia_licenca: README lido em texto bruto em 2026-09-08 (https://raw.githubusercontent.com/zed-industries/zed/main/README.md, seção "Licensing"): "Zed source code is licensed primarily under GPL-3.0-or-later, with Apache-2.0 components where marked." Verificado no manifesto de cada crate na mesma data: crates/zed/Cargo.toml declara license = "GPL-3.0-or-later"; crates/collab/Cargo.toml declara license = "GPL-3.0-or-later"; crates/gpui/Cargo.toml declara license = "Apache-2.0". Arquivos LICENSE-GPL (texto da GNU GPL v3) e LICENSE-APACHE presentes na raiz (HTTP 200); LICENSE-AGPL retorna HTTP 404 hoje. O passado AGPL está documentado na issue pública https://github.com/zed-industries/zed/issues/5383, que discute o arquivo LICENSE-AGPL e crates declarando "AGPL-3.0-only". Data exata do relicenciamento de AGPL para GPL: NAO_VERIFICADO — motivo: não localizamos anúncio primário do fornecedor datando a mudança, apenas o estado atual dos manifestos e o registro histórico da issue.
- redistribuivel: não, para o nosso caso — o código GPL-3.0-or-later é redistribuível apenas sob a própria GPL, o que contaminaria a obra derivada e conflita com a política de licenças deste repositório (o portão `gate:licenses` recusa a família copyleft forte/fonte-disponível). O crate gpui, sob Apache-2.0, é a única peça tecnicamente reutilizável — e ainda assim está fora, porque o prompt mestre proíbe incorporar código do Zed sem distinção de crate.
- marcas: "Zed" é marca e nome comercial da Zed Industries, Inc.; o logotipo é obra protegida. Nem a GPL nem a Apache-2.0 concedem direitos de marca (a Apache-2.0 exclui marcas expressamente em §6). Uso permitido: citação nominal e comparação técnica; uso proibido: nome ou logo em produto ou material nosso, e qualquer sugestão de origem ou endosso.
- dependencias_e_lockfiles: projeto Rust em workspace Cargo, com Cargo.lock versionado na raiz (https://raw.githubusercontent.com/zed-industries/zed/main/Cargo.lock, HTTP 200 em 2026-09-08). O próprio projeto trata licença de dependência como bloqueio de CI: o README manda usar `cargo-about` e manter a lista aceita em script/licenses/zed-licenses.toml. Conteúdo transitivo do Cargo.lock: NAO_VERIFICADO — motivo: não baixamos o lockfile, e não há razão para auditá-lo enquanto a decisão for não usar o código.
- rede_filesystem_segredos: rede — o editor é multiplayer e fala com o serviço de colaboração da Zed (crate collab) e com provedores de IA/agente por chave; filesystem — é um editor desktop, com leitura e escrita irrestritas nos diretórios que o usuário abre; segredos — chaves de provedores de IA ficam na configuração local do usuário. Registro relevante: a CVE-2025-68432 mostra que o próprio Zed carregava configuração de LSP a partir de `.zed/settings.json` DENTRO do projeto aberto, o que faz do filesystem um vetor de execução — a correção foi introduzir confiança por worktree. Telemetria e detalhes de rede por versão: NAO_VERIFICADO — motivo: não executamos o produto nem inspecionamos o tráfego.
- cves_conhecidas: CVE-2025-68432 — execução arbitrária de código no Zed em versões anteriores a 0.218.2-pre: o editor carregava configurações de Language Server a partir do arquivo `.zed/settings.json` do projeto sem validação, de modo que abrir um projeto malicioso executava comandos com os privilégios do usuário; CVSS v3.1 7.7 (High); correção introduziu mecanismo de confiança por worktree. Fonte: https://osv.dev/vulnerability/CVE-2025-68432, consultada em 2026-09-08. Lição direta para nós: configuração vinda do repositório aberto é entrada não confiável, e qualquer recurso nosso que leia config de projeto precisa de um gate de confiança explícito.
- sbom: não há SBOM oficial publicado na raiz do repositório (nenhum arquivo NOTICE ou SBOM encontrado em 2026-09-08); o equivalente funcional do projeto é o relatório de licenças gerado por `cargo-about` a partir do Cargo.lock. Como não usamos o código, não há SBOM a produzir do nosso lado.
- sast: não executado — motivo objetivo: nada do Zed foi copiado para este repositório, então não há código dele sob alcance dos nossos scanners; escanear o upstream exigiria clonar código copyleft que a política manda não trazer
- poc_isolado: nenhum PoC de código foi feito e nenhum deve ser feito com o código-fonte — motivo: mesmo compilar e derivar localmente aumentaria o risco de contaminação por leitura de fonte copyleft. Estudo permitido: usar o Zed COMO PRODUTO (binário instalado), observar comportamento de UX e desempenho, sem consultar nem derivar o código-fonte.
- veredito: não — nada de copiar código do Zed, e este é o caso mais explícito dos seis: o prompt mestre proíbe, a licença GPL-3.0-or-later contaminaria a obra derivada e o portão de licenças deste repositório recusa a família copyleft forte; pode-se estudar o produto pelo binário e aprender com defeitos públicos como a CVE-2025-68432, sem qualquer contato derivativo com o código.
